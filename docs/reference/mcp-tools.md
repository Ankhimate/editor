# MCP tool reference

> Generated by `cargo run -p xtask -- docs-sync`. Do not edit manually.

Tools are listed in session workflow order. Schemas are exact registry output.

## `open_rig`

Open a rig through the shared importer registry. .ankh and PSD are built in; installed JavaScript plugins can add formats such as Spine and DragonBones. Returns a setup-pose preview and a compact inventory of image assets and attachment choices. Replaces whatever was open.

```json
{
  "properties": {
    "path": {
      "description": "Absolute path to the file",
      "type": "string"
    }
  },
  "required": [
    "path"
  ],
  "type": "object"
}
```

## `new_rig`

Start an empty rig. Use this when building from a description rather than editing an existing file.

```json
{
  "properties": {
    "name": {
      "type": "string"
    }
  },
  "required": [
    "name"
  ],
  "type": "object"
}
```

## `describe_rig`

The open rig's full structure as JSON: bones, slots, skins, animations and their keys. This is the same context an export template sees, documented in docs/export-context.md.

```json
{
  "properties": {},
  "type": "object"
}
```

## `list_verbs`

Every verb `run_script` can invoke, with the arguments each takes. Call this before writing a script that uses anything beyond creating bones.

```json
{
  "properties": {
    "prefix": {
      "description": "Only verbs starting with this — `bone.`, `anim.`",
      "type": "string"
    }
  },
  "type": "object"
}
```

## `run_script`

Run JavaScript against the open rig. `ops.invoke(verb, args)` performs an edit, `rig()` reads the structure, `names()` lists what exists, `console.log` reports back. Edits persist for the rest of the session. Prefer one script over many calls.

```json
{
  "properties": {
    "script": {
      "description": "JavaScript source",
      "type": "string"
    }
  },
  "required": [
    "script"
  ],
  "type": "object"
}
```

## `save_rig`

Write the open rig to a path. Refuses to write over the file it was opened from: there is no undo here, so a mistake would leave nothing to go back to.

```json
{
  "properties": {
    "path": {
      "description": "Where to write it",
      "type": "string"
    }
  },
  "required": [
    "path"
  ],
  "type": "object"
}
```

## `export_rig`

Export through a saved/built-in template preset or an installed JavaScript exporter. Paths rendered by the preset are confined to the output directory; the complete plan is rendered before writing and nothing is deleted.

```json
{
  "properties": {
    "output_dir": {
      "description": "Directory to write into",
      "type": "string"
    },
    "preset": {
      "description": "Preset name, or plugin exporter id/label; defaults to Ankhimate runtime",
      "type": "string"
    }
  },
  "required": [
    "output_dir"
  ],
  "type": "object"
}
```
